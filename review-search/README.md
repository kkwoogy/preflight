# 찐후기 — 광고 빼고 보는 후기 검색

블로그에서 물건 후기를 찾으면 쿠팡 파트너스 글, 체험단 글, 원고료 받은 글이 위를 다 차지한다. 찐후기는 네이버·다음의 블로그·카페 글을 **공식 검색 API**로 찾고, 블로그 글은 **본문을 직접 열어서** 광고 표시가 있는지 본 다음 걸러서 보여준다. 글마다 왜 그렇게 판단했는지 근거 문구를 같이 보여준다.

```
검색어 → 네이버 블로그·카페, 다음 블로그·카페 (공식 API)
       → 같은 글 합치기 → 블로그 본문 열기 (네이버 블로그, 티스토리, 브런치)
       → 광고 표시·제휴 링크·체험단 배너 찾기 → 찐후기 / 광고 표시 없음 / 의심 / 광고·협찬
```

## 어떻게 거르나

광고 표시는 보통 글 맨 위나 맨 아래에 있어서, 검색 API가 주는 요약(150자 정도)에는 잘 안 보인다. 그래서 본문을 연다.

| 판정 | 기준 |
|---|---|
| **광고·협찬** | 아래 중 하나라도 있으면. 근거가 하나는 꼭 있다.<br>· 제휴 문구: "쿠팡 파트너스 활동의 일환으로", "쇼핑 커넥트 활동", "수수료를 제공받습니다"<br>· 협찬 문구: "소정의 원고료를 지원받아", "제품을 무상으로 제공받아", "업체로부터 협찬받아", "#광고", "[협찬]", "유료광고 포함", "체험단에 선정되어"<br>· 링크: `link.coupang.com`, `coupa.ng`, 쿠팡 파트너스 배너, 알리 `s.click.aliexpress.com`, 링크프라이스, 텐핑, 애드픽<br>· 체험단 배너: 레뷰, 리뷰노트, 디너의여왕, 강남맛집, 미블, 서울오빠, 포블로그 등 23곳 |
| **광고 의심** | 하나로는 단정할 수 없는 신호가 쌓이면 (40점). "추천 TOP 7"·"최저가 비교" 제목, 쇼핑몰 링크 3개 이상, "서포터즈", "후기 이벤트" 등 |
| **찐후기 가능성 높음** | 광고 표시가 없고, 직접 써 본 사람이 남기는 말이 있으면: "내돈내산", "3개월 써보니", 단점·아쉬운 점·반품, 재구매 |
| **광고 표시 없음** | 본문을 봤는데 광고 표시도, 직접 써 본 티도 딱히 없으면 |
| **본문 미확인** | 카페 글처럼 로그인해야 보이는 글. 요약만 보고 판단한다 |

헷갈리기 쉬운 경우도 처리한다.

- "협찬 아님", "원고료 없이", "광고 X" → 광고가 아니라고 밝힌 것으로 본다.
- "체험단 후기만 많아서 직접 샀어요" → 체험단이라는 단어만 나온 건 약한 신호(10점)라서 광고로 보지 않는다.
- "내돈내산"이라고 써 놓고 아래에 원고료 문구가 있으면 → 광고. "‘내돈내산’이라고 썼지만 광고 문구가 같이 있음"으로 따로 표시한다. 업체가 "내돈내산"으로 쓰게 시킨 사례가 실제로 보도됐다 ([KBS, 2025-11](https://v.daum.net/v/20251112214051572)).
- 티스토리의 "같은 카테고리 다른 글" 목록과 사이드바 광고는 본문에서 빼고 본다.

규칙은 전부 [`lib/rules.mjs`](lib/rules.mjs) 한 파일에 있다. 문구나 도메인을 더하려면 거기에 한 줄 넣고 [`test/classify.test.mjs`](test/classify.test.mjs)에 예문을 넣으면 된다.

## 무신사·에이블리 후기는 왜 안 긁어오나

- **공식 API가 없다.** 무신사·에이블리·지그재그·올리브영 모두 후기를 외부에 열어 주는 API가 없다. 앱 안의 비공개 API를 흉내 내야 하는데, 사이트가 바뀌면 바로 깨지고 대부분 약관에서 크롤링을 금지한다.
- **법적 위험이 있다.** 남의 사이트 데이터를 대량으로 가져와 내 서비스에 보여주는 건 저작권법상 데이터베이스제작자의 권리와 부정경쟁방지법 위반으로 소송이 난 사례가 있다 (잡코리아 대 사람인 등). 혼자 보는 도구여도 공개 사이트로 띄우는 순간 문제가 된다.
- **필요도 덜하다.** 쇼핑몰 후기는 산 사람만 쓸 수 있어서 블로그보다 광고 비율이 훨씬 낮다. 무신사는 체험단 후기를 따로 구분한다는 자료도 있다 (화면에서 직접 확인하지는 못했다).

그래서 쇼핑몰은 **그 사이트 검색으로 바로 가는 링크**만 준다 (무신사, 에이블리, 지그재그, 올리브영, 쿠팡, 네이버쇼핑).

## 구글은?

구글의 검색 API(Custom Search JSON API)는 신규 가입을 받지 않는다. 기존 사용자도 2027-01-01까지만 쓸 수 있다 ([공지](https://developers.google.com/custom-search/v1/overview)). 대신 **광고 문구를 뺀 구글 검색 링크**를 만들어 준다.

- `에어랩 후기 -"파트너스 활동" -"수수료를 제공" -"원고료" -"제공받아" -"협찬받아" -"체험단"`
- 커뮤니티만: `에어랩 후기 (site:clien.net OR site:ppomppu.co.kr OR site:theqoo.net OR …)`. 클리앙, 뽐뿌, 더쿠, 에펨코리아, 디시, 루리웹, 인스티즈, 82쿡이 들어간다.

"협찬"은 일부러 빼지 않았다. 빼면 "협찬 아님"이라고 쓴 글까지 같이 빠진다. 이 링크들은 서버 없이도 동작해서, 이 페이지를 GitHub Pages로 열어도 쓸 수 있다.

## 직접 돌리기

Node 20.3 이상이 필요하다. 설치할 패키지는 없다.

### 1. API 키 받기 (무료)

**네이버** (하루 25,000회)
1. https://developers.naver.com/apps → 애플리케이션 등록
2. 사용 API에서 **검색**을 고른다.
3. 비로그인 오픈 API 서비스 환경에서 **WEB 설정**을 고르고 `http://localhost`를 넣는다.
4. 등록하면 나오는 Client ID와 Client Secret을 복사한다.

**카카오** (다음 검색)
1. https://developers.kakao.com → 내 애플리케이션 → 애플리케이션 추가하기
2. 앱 → 플랫폼 키에서 **REST API 키**를 복사한다.

둘 중 하나만 있어도 된다.

### 2. 켜기

```bash
cd review-search
cp .env.example .env      # 키를 채운다
node server.mjs           # → http://localhost:8787
```

검색 한 번에 드는 API 호출:
- 네이버 최대 4회. "○○ 후기"와 "○○ 내돈내산" 두 검색어 × 블로그·카페.
- 다음도 최대 4회.
- 그래서 네이버 키 하나로 하루 약 6,000번 검색할 수 있다.
- 같은 검색은 30분 동안 다시 부르지 않는다.

### 3. 시험

```bash
npm test                  # node --test test/*.test.mjs, 네트워크 없이 돈다
```

### 서버에 올리기

Render, Railway, Fly.io처럼 Node를 돌릴 수 있는 곳이면 된다.
1. 시작 명령은 `node server.mjs`로 한다.
2. 환경 변수에 키와 `HOST=0.0.0.0`을 넣는다.

GitHub Pages는 정적 파일만 올리므로 링크 기능만 동작한다.

## API

| 요청 | 응답 |
|---|---|
| `GET /api/health` | `{ ok, sources: ["네이버 블로그", …] }` |
| `GET /api/search?q=에어랩&sort=sim\|date` | Server-Sent Events: `results`(전체 목록, 요약 기준 판정) → 본문을 읽을 때마다 `update` → `done` |
| `GET /api/search?q=에어랩&stream=0` | 본문 확인까지 끝난 결과를 JSON 하나로 |

## 한계

- 표시를 아예 안 한 광고는 못 거른다. 업체가 일반인 이름으로 올리는 카페 바이럴도 마찬가지다. 공정위가 2024년에 찾아낸 표시 위반 의심 글만 22,011건이다 ([경향, 2025-03](https://www.khan.co.kr/article/202503161200011)). 그래서 판정과 함께 근거를 항상 보여준다.
- 카페 글은 대부분 로그인해야 보여서 본문을 열지 않는다.
- 판정 규칙은 문구를 찾는 방식이다. "순위형 제목" 같은 약한 신호에는 공식 근거가 없다. 그래서 그것만으로는 '의심'까지도 가지 않게 했다.
- 네이버 블로그 HTML 구조(`se-main-container`)가 바뀌면 본문을 못 읽고 '본문 미확인'으로 남는다.
- 이 개발 환경에서는 네이버·카카오 서버에 접속할 수 없었다. 그래서 실제 API 응답이 아니라 문서에 맞춘 가짜 응답으로 시험했다. 키를 넣고 처음 돌릴 때 결과를 한 번 살펴봐야 한다.

## 지켜야 할 것

- **블로그 본문 열기**
  - 사용자가 검색한 결과에 나온 글만 연다. 검색 한 번에 최대 40개, 동시에 6개까지다.
  - `blog.naver.com`의 robots.txt는 일반 크롤러에게 글 페이지를 허용한다.
  - 다만 **AI 학습·RAG 목적의 봇은 명시적으로 금지**한다. 이 도구는 AI를 쓰지 않는다. 본문을 LLM에 넣어 요약하는 기능을 붙이려면 이 조건부터 다시 확인해야 한다.
  - 본문을 열고 싶지 않으면 `CHECK_BODIES=0`으로 끈다.
- **검색 결과 보여주기**
  - 화면에는 API가 준 제목·요약, 원문 링크, 판정 근거가 된 짧은 문구(40자 안팎)만 보여준다.
  - 본문은 판정에만 쓰고, 서버 메모리에 30분 캐시할 뿐 저장하지 않는다.
  - 다만 다음 검색 결과를 걸러서 보여주는 게 카카오 운영정책에 맞는지 개발자 포럼에 질문이 올라와 있다. 공개 서비스로 띄우기 전에 확인해야 한다.
