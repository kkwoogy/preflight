# 타깃별 프롬프트 규칙

**확인일: 2026-10-04.** 모델 이름과 기능은 매달 바뀐다. 그래서 이렇게 한다:

- **버전 이름보다 종류로 고르게 한다** (빠른 모델 / 생각하는 모델 / 최상위 모델).
- **모르는 모델이나 기능이 나오면**, 웹 검색을 쓸 수 있을 때 그 회사의 공식 프롬프트 가이드를 확인하고 쓴다. 쓸 수 없으면 아래 "공통 규칙"만 쓴다.
- **"(비공식)"** 표시는 공식 문서에서 확인하지 못한 내용이다.

## 공통 규칙 (모든 텍스트 AI)

- **내용이 형식보다 중요하다.** 목표, 맥락과 이유, 독자, 결과물 형식, 성공 기준이 구체적이어야 한다. 최신 큰 모델일수록 형식 차이에는 덜 민감하지만, 내용이 애매하면 어떤 모델이든 결과가 갈린다.
- **한 프롬프트에 결과물 하나.** 여러 개를 한꺼번에 시키면 각각이 얕아진다.
- **지시끼리 모순이 없어야 한다.** 최신 모델은 지시를 문자 그대로 따르기 때문에, 모순되면 빠진 정보보다 더 해롭다.
- **소리치지 않는다.** "반드시!!", "절대!!" 같은 말은 꼭 지켜야 하는 조건에만 쓴다. 남발하면 오히려 해롭다.
- **"하지 마" 대신 "이렇게 해"로 쓴다.** 예: "글머리표 쓰지 마" → "문단으로 이어서 써줘"
- **생각하는 모델에게 "단계별로 생각해"를 넣지 않는다.** 이미 안에서 생각한다. 어려운 일이면 생각 수준을 높이라고 준비물에 적는다.
- **긴 자료는 위에, 질문은 맨 아래에.** 자료는 `<자료>` … `</자료>` 같은 태그로 감싼다.
- **사실이 중요한 일**에는 출처, 확실하지 않은 부분 표시, 가정 목록을 요청한다.

## ChatGPT

**모델 선택지** (Plus·Pro 기준): `Instant` / `Thinking (중간·높음)` / `Pro` / `모르겠어 (기본 설정)`

- Instant는 스스로 더 깊게 생각하지 않는다. 2026-09부터 자동 전환이 없어졌다. 그래서 분석·코드·여러 단계가 필요한 일이면 **준비물에 "Thinking 선택"을 적는다.** 프롬프트에 "더 깊게 생각해"라고 써도 수준은 바뀌지 않는다.
- 무료·Go 요금제는 `Instant` / `Think`만 있다.

**형식**
- `# 맥락 / # 지시 / # 제약` 같은 마크다운 제목으로 나눈다. 붙여넣는 문서는 XML 태그로 감싼다.
- 독자, 형식, 분량, 완료 기준을 적는다. 단계를 일일이 지시하기보다 결과와 기준을 적는다.
- "짧게"라고만 쓰면 너무 짧아질 수 있다 (GPT-5.6이 원래 간결하다). 무엇을 남기고 무엇을 뺄지 적는다.
- 줄글을 원하면 "문단으로"라고 명시한다. 최신 모델은 목록이나 표로 쓰는 경향이 있다.
- 예시는 형식이 까다로울 때만 넣고, 지시와 정확히 일치하게 한다.

**켤 기능**
- 웹 검색: 최신 정보가 필요할 때
- Deep Research (+ 메뉴): 출처가 있는 조사 보고서가 필요할 때. 범위, 기간, 결과 형식을 프롬프트에 적는다. 계획을 먼저 보여주고 고칠 수 있다.
- 프로젝트: 자료를 계속 참고해야 할 때
- 이미지 생성 (Images 2.5)
- Work 모드: 문서·시트·슬라이드 완성본이 필요할 때 (유료)

**하지 말 것**
- Canvas 안내: GPT-5.5 이상에서 없어졌다.
- 맞춤 GPT 만들기 안내: 개인 요금제는 만들 수 없고, 2026-12-11에 종료된다.
- 사용자의 맞춤 지침이나 프로젝트 지침과 부딪히는 지시

**전달**: `https://chatgpt.com/`

## Claude

**모델 선택지**: `Haiku (빠름)` / `Sonnet (일상 작업)` / `Opus (어려운 일·긴 작업)` / `Fable (가장 강력)` / `모르겠어 (기본 설정)`

**형식**
- 명확하고 직접적으로 쓴다. "유능하지만 새로 온 동료"에게 설명하듯이.
- 지시마다 **이유**를 붙인다. Claude는 이유를 이해하면 규칙을 더 잘 일반화한다.
- 구조는 XML 태그로 나눈다: `<맥락>`, `<지시>`, `<예시>`, `<자료>`
- 형용사 대신 예시 1~3개를 넣는다.
- "하지 마"보다 "이렇게 해"로 쓴다.
- 긴 문서를 먼저 넣고 질문을 맨 아래에 둔다.
- 한 문장으로 역할을 준다.
- "다시 한 번 확인해"를 과하게 넣지 않는다. 최신 모델은 스스로 검증한다.
- "제안해줘"와 "바꿔줘"를 구분한다.

**켤 기능**: 웹 검색, 리서치, 프로젝트(자료와 지침), 파일 첨부, 커넥터(Drive 등), 아티팩트(결과물 페이지)

**전달**: `https://claude.ai/new`

## Gemini

**모델 선택지**: `Flash-Lite` / `Flash (기본)` / `Pro` / `모르겠어 (기본 설정)`. 생각 수준은 따로 고른다: `기본` / `Extended` / `Deep Think` (Ultra 요금제 + Pro 모델만).

- 어려운 일이면 **준비물에 "Pro + Extended 선택"을 적는다.**
- 무료 요금제는 Pro 사용이 제한되고, 문맥 길이가 약 32k 토큰이다. 긴 자료를 붙여넣으면 잘리니 요약하거나 파일로 올리게 한다.

**형식**
- 목표를 정확하고 직접적으로 쓴다. 과장된 말을 뺀다.
- 구분 방식은 XML 태그나 마크다운 제목 중 하나로 통일한다.
- 역할, 꼭 지킬 조건, 결과 형식을 **맨 앞에** 둔다.
- 긴 자료는 먼저 넣고 질문은 맨 끝에 "위 자료를 바탕으로…"로 시작한다.
- Gemini 3.x는 기본적으로 짧게 답한다. **원하는 분량, 자세함, 말투를 명시한다.**
- 단계별 추론을 요구하지 않는다.
- 예시는 구조와 형식이 모두 똑같아야 한다.
- 애매한 용어는 정의한다. 첨부한 이미지·파일·영상은 하나하나 직접 언급한다.
- 날짜가 중요한 질문이면 오늘 날짜를 적는다.

**켤 기능**
- Deep Research: 출처를 Gmail, Drive, 업로드 파일로 지정할 수 있다. 실행 전에 계획을 고칠 수 있다.
- Canvas: 문서·슬라이드·앱
- 이미지 (Nano Banana 2, 더 좋은 품질은 "Pro로 다시")
- 영상 (Gemini Omni)
- `@` 앱 연결 (Gmail, Drive, YouTube 등)

**전달**: `https://gemini.google.com/app`

## Perplexity

**선택지**: `검색 (기본)` / `Deep Research` / `파일·앱 만들기`

**형식**
- 정확한 검색 요청서처럼 쓴다. 대상, 기간, 원하는 단위를 적는다. 예: "2025 회계연도 사업부문별 매출"
- 최신성과 출처 선호를 명시한다. 예: "2026년 1월 이후", "공식 자료·논문 우선"
- 키워드만 던지지 말고 완전한 질문으로 쓴다.
- 결과 형식(표, 목록)을 요청한다.

**하지 말 것**
- **예시 답변을 넣지 않는다.** 검색이 예시의 주제에 끌려간다. 구조만 보여주는 건 괜찮다.
- URL을 기억해서 만들어달라고 하지 않는다.
- 프롬프트에 적은 기간 제한이 반드시 지켜진다고 믿지 않는다.

**전달**: `https://www.perplexity.ai/`

## 채팅 앱 이미지 생성 (ChatGPT Images 2.5 · Gemini Nano Banana 2)

**형식**
- 완전한 문장으로, 장면 → 대상 → 주요 디테일 → 제약 순서로 쓴다. 용도를 적는다 (광고, 포스터, 제품 사진).
- 재질, 조명, 렌즈, 구도를 구체적으로 쓴다. 사진처럼 보이길 원하면 "사실적인 사진"이라고 명시한다.
- 긍정형으로 쓴다. 예: "차 없이" → "텅 빈 거리"
- **이미지 안 글자**: 정확한 문구를 따옴표로 넣고, 글꼴·크기·색·위치를 적고, "다른 글자 없이"를 붙인다.
- 참고 이미지가 여러 장이면 번호를 붙이고 역할을 준다 (대상 / 스타일 / 배경).

**고칠 때**
- "X만 바꾸고 Y는 그대로"라고 쓴다.
- 한 번에 하나만 바꾼다.
- 80% 맞은 이미지는 새로 뽑지 말고 고친다.

## Midjourney (V8.2 기준)

**형식**
- 주제를 먼저 쓰고, 디테일 → 배경 → 분위기 → 조명 → 매체·카메라 순서로 쓴다. 파라미터는 맨 끝에 둔다.
- V8은 키워드 나열보다 **구체적인 문장**에 강하다. "8k, masterpiece" 같은 말은 뺀다.
- 빼고 싶은 건 문장에 쓰지 말고 `--no`로 뺀다.
- 이미지 안 글자는 "큰따옴표"로 짧게 쓴다.

**주요 파라미터**
- `--ar` (비율)
- `--s` (0~1000, 기본 100)
- `--chaos` (0~100)
- `--raw` (사실적이고 통제된 느낌)
- `--no`
- `--seed`
- `--sref` (스타일 참고)
- `--p` (개인화)
- `--hd`

**하지 말 것**: V7 전용 파라미터(`--oref`, `--cref`)를 쓰지 않는다. 부분 수정은 Edit 기능으로 한다.

## Suno (v6 기준)

**두 칸으로 나눠서 준다:**
- **스타일 칸**: 장르·시대, BPM, 조성, 보컬 종류, 악기, 분위기, 사운드. 예: "밝은 팝, 110 BPM, 여성 보컬, 신스 훅". 1,000자 이내 (비공식).
- **가사 칸**: 구간 태그를 쓴다. `[Intro] [Verse 1] [Pre-Chorus] [Chorus] [Bridge] [Outro]`, `[Instrumental]`, `[Guitar Solo]`
- 빼고 싶은 스타일은 **Exclude Styles 칸**에 넣는다.

**참고**
- v6는 오디오 입력을 받는다. 흥얼거린 녹음 파일을 쓸 수 있는 곳이다.
- 태그는 강한 힌트일 뿐 명령이 아니다.
- 칸 길이를 넘는 부분은 아무 말 없이 잘린다.

## 영상 (Veo 3.1 · Gemini Omni)

**형식**
- 공식처럼 쓴다: [촬영 방식] + [대상] + [동작] + [배경] + [스타일과 분위기]
- 샷 크기, 각도, 카메라 움직임, 렌즈를 적는다.
- 동작은 박자로 나눠 쓴다. 예: "네 걸음 걷고, 멈춘다"
- 대사는 `여자가 말한다, "이제 가야 해."`처럼 쓰고, 효과음은 `SFX:`, 배경음은 `Ambient:`로 적는다.
- 영상 길이, 해상도, 비율은 프롬프트가 아니라 설정에서 고른다.

**하지 말 것**
- **Sora는 서비스가 종료됐으니 타깃으로 제안하지 않는다.**
- 클립 길이에 비해 너무 많은 동작을 넣지 않는다.

## 코딩 도구 (Cursor · Copilot · Codex · Claude Code)

**형식**: **목표 / 맥락 / 제약 / 완료 조건**

- 파일, 폴더, 에러 메시지, 따라 할 기존 패턴을 이름으로 적는다. 범위 밖인 것도 적는다.
- 실행해서 확인할 방법(테스트, 빌드, 스크린샷)을 주고, 실제로 돌려서 증거를 보여달라고 한다.
- 버그는 증상, 의심 위치, "실패하는 테스트를 먼저 쓰고 고쳐"로 쓴다.
- 여러 파일에 걸치거나 애매한 일은 계획 모드부터 쓴다. 세션 하나에 작업 하나.

**규칙 파일**: 반복되는 지시는 각 도구의 규칙 파일로 보내라고 제안한다 (`AGENTS.md`, `CLAUDE.md`, `.cursor/rules`, `copilot-instructions.md`).
