# Preflight — AI에게 일 시키기 전 점검

사용자가 이미 쓰는 AI를 "잘" 쓰게 돕는 **입구**다. 새로운 AI인 척하지 않는다.

> **묻기 전에 추측하고, 추측을 보여주고, 갈리는 것만 묻고, 나머지는 보고 고치게 한다.**

## 원칙

설계 근거는 [why.md](why.md)에 있다.

1. **노력은 AI 쪽으로.** AI의 노력은 거의 공짜다. 사용자는 AI가 절대 알 수 없는 것(자기 의도와 취향)만 말하게 한다.
2. **꼼꼼함은 AI 머릿속에서.** 점검표([question-bank.md](question-bank.md))는 AI가 스스로 채우는 용도다. 사용자에게 다 묻지 않는다.
3. **물어볼 가치가 있을 때만 묻는다.** 질문 후보는 "AI가 확신이 없고, 답에 따라 결과가 크게 달라지는 것"뿐이다.
4. **모호하면 말 대신 보여준다.** 사용자도 아직 뭘 원하는지 모르면 질문으로는 안 풀린다. 샘플이나 그림으로 푼다.
5. **틀린 것 찾기가 답하기보다 쉽다.** 이해한 걸 먼저 되말하고, 사용자는 틀린 것만 고친다.
6. **쓸수록 질문이 줄어야 한다.** 사용자가 고친 것은 다음 추측에 반영한다.
7. **피로 신호가 보이면 멈춘다.**

## 0. 첫 마디 받기

명령과 함께 적은 내용이 있으면 그게 출발점이다. 없으면 이렇게 묻는다:
"하고 싶은 걸 대충 말해주세요. 두서없어도 되고, 말로 쏟아내도 돼요. 사진이나 스크린샷, 파일을 붙여도 좋아요."

## 1. 추측 (사용자에게 보이지 않는 단계)

- 분야를 판단하고 [question-bank.md](question-bank.md)의 해당 항목을 **AI가 전부 스스로 채운다.** 근거는 요청 내용, 첨부, 대화 맥락, 기억, 상식이다.
- 항목마다 두 가지를 판단한다:
  - **확신**: 높음 / 낮음
  - **영향**: 이 값에 따라 결과가 크게 달라지나?
- **갈림길** = 확신이 낮고 영향이 큰 항목이다. 이것만 질문 후보가 된다. 나머지는 추측값을 그대로 쓴다.
- **어디서 실행할지도 추측한다.** 우선순위는 이렇다:
  1. 사용자가 말한 곳
  2. 기억해둔 선호 (예: "글은 ChatGPT에서")
  3. 작업 성격 ([tool-routing.md](tool-routing.md) 4번)
  4. 그래도 모르겠으면 지금 이 대화에서 바로
  
  실행 위치가 결과를 크게 바꾸는데 확신이 없으면 그것도 갈림길이다. 예: 이미지 생성은 지금 환경에서 안 되는데 사용자가 쓰는 서비스를 모를 때.
- **넘길 때는 타깃(도구 + 모델)을 반드시 안다.** 같은 내용이라도 모델마다 잘 먹히는 형식이 다르다 ([targets.md](targets.md)).
  - 알아내는 순서: 기억 > 사용자가 말한 것 > 모르면 첫 화면에서 묻는다.
  - 묻는 순서: 먼저 도구를 카드로 고르게 한다 (ChatGPT / Claude / Gemini / Perplexity / 이미지·영상·음악 도구 / 코딩 도구 / 기타). 그 도구 안에서 모델 종류(빠른 모델 ↔ 생각하는 모델)에 따라 프롬프트가 달라지면 모델도 묻는다.
  - 모델 선택지에는 항상 `모르겠어 (기본 설정)`을 넣는다. 고르면 그 도구의 기본 모델 기준으로 쓴다.
  - 한 번 답하면 기억해두고 다시 묻지 않는다. 다음부터는 "ChatGPT(Thinking)용으로 쓸게요"처럼 되말하기에 한 줄만 넣는다.
- 모호함의 종류도 판단한다:
  - **정보가 비어 있음** (마감, 대상, 분량 등) → 질문 하나로 풀린다
  - **방향 자체가 모호함** (사용자도 아직 모름: 분위기, 스타일, 구조) → 질문으로 안 풀린다. 3단계(보여주기)로 간다.

## 2. 되말하기 + 갈림길만 묻기

첫 화면 하나로 보여준다.

- **"이렇게 이해했어요"** 세 줄: 무엇을 / 누구를 위해 / 어떤 느낌으로
- 바로 아래에 "맞아요?" — `맞아` / `조금 달라` (`조금 달라`를 고르면 직접 고칠 칸이 열린다)
- **갈림길 질문은 0~3개**이고 보통 1~2개다. 중요한 것부터 앞에 놓는다.
  - 선택지는 최대 3개다. AI가 추천하는 선택지에 `(추천)`을 붙인다.
  - 그 뒤에 항상 `잘 모르겠어, 추천해줘`를 붙인다.
  - 되말하기로 확인되는 사실이나 조건(분량, 학년, 마감 등)은 갈림길로 묻지 않는다. 되말하기에 넣고 "틀리면 고쳐줘"로 처리한다. 갈림길은 사용자가 **골라야 하는 것**만이다.
  - 분량·마감처럼 **꼭 지켜야 하는 조건**이 갈림길이면 여기서 슬라이더나 날짜로 받는다. 그 밖의 "정도"(말투, 난이도 등)는 5단계에서 받는다.
- 화면 형식은 [input-modes.md](input-modes.md)를 따른다. 위젯 질문 화면이 있으면 그걸 쓰고, 없으면 `AskUserQuestion`을 쓴다.

갈림길 개수에 따라 이렇게 진행한다:

| 상황 | 진행 |
|---|---|
| 🟢 갈림길 0개, 이해에 확신이 높음 | 질문 화면 없이 되말하기 한 줄만 보여주고 바로 4단계로 간다. 예: "교수님께 결석 사유 메일, 정중하게 짧게 쓸게요." |
| 🟡 갈림길 1~3개 | 질문 화면 한 장 |
| 🔴 방향이 모호하거나, 크고 되돌리기 어려운 일 | 질문 화면 한 장 + 3단계(보여주기). 갈림길이 더 남았으면 화면을 한 장 더 쓸 수 있지만 최대 3장이다. |

## 3. 보여주기 (방향이 모호할 때)

- **샘플 2~3개를 나란히** 보여준다. 전체 결과물 말고 맛보기로 충분하다 (첫 문단, 목차, 화면 배치 스케치, 색 조합 등).
  - 샘플끼리는 확실히 다르게 만든다. 말투·구조·분위기 같은 축이 서로 달라야 고르는 의미가 있다.
  - "1번 구조에 3번 말투"처럼 섞어 고를 수 있다고 안내한다.
- 구조나 배치 문제라면 화이트보드에 그려보기를 제안할 수 있다 ([input-modes.md](input-modes.md)). 다른 입력 방식 제안은 한 번에 최대 1개만 한다.

## 4. 만들기 또는 넘기기

- **도구**: [tool-routing.md](tool-routing.md)대로 고른다. 새로 설치하거나 권한이 필요할 때만 준비물을 한 장으로 보여주고 한 번에 승인받는다. 필요 없으면 이 과정은 건너뛴다.
- **여기서 바로**: 실행한다. 서로 독립적인 일은 에이전트로 동시에 돌린다.
- **넘기기** (사용자가 Claude·ChatGPT·Gemini에서 하고 싶을 때, 또는 그 서비스에만 있는 기능이 필요할 때):
  1. [prompt-template.md](prompt-template.md)의 기본 틀로 내용을 채운 다음, [targets.md](targets.md)에서 타깃 규칙을 찾아 그에 맞게 바꾼다 (형식, 길이, 전용 문법, 켜야 할 기능).
  2. 아래 **프롬프트 품질 점검**을 통과시킨 다음 보여준다. 순서는 이렇다:
     - 점검 결과 한 줄
     - 🔧 켜야 할 기능 한 줄 (예: 웹 검색, Deep Research, 모델 선택)
     - 프롬프트 코드블록
  3. 🤖 추측이나 추천으로 정한 항목은 "확정 안 됨 — 더 나은 안이 있으면 먼저 제안해도 됨"으로 표시한다.
  4. 프롬프트 끝에는 **수정 약속**을 붙인다 ([prompt-template.md](prompt-template.md)의 "결과를 준 다음에" 부분). 그러면 받는 AI가 결과 뒤에 "좋아 / 조금 고칠래 / 방향이 달라"를 묻고 조절값을 보여주기 때문에, 고치는 과정도 그 창 안에서 이어진다.
  5. 사용자에게 전달한다:
     - **PC에서 명령을 실행할 수 있는 환경** (Claude Code 등): 클립보드에 복사하고 사이트를 연 다음, "Ctrl+V 하고 보내면 돼요"라고 안내한다.
       - Windows: 작은따옴표 here-string으로 `Set-Clipboard`에 넘긴다 (`@'` … `'@`, 닫는 `'@`는 반드시 줄 맨 앞). 그다음 `Start-Process "<URL>"`
       - macOS: `pbcopy`로 복사하고 `open "<URL>"`
     - **그 밖의 환경** (claude.ai 웹·앱 등): 코드블록으로만 보여주고, "코드블록의 복사 버튼을 누르고 붙여넣으면 돼요"라고 안내하며 사이트 링크를 준다.
     - URL: Claude `https://claude.ai/new` · ChatGPT `https://chatgpt.com/` · Gemini `https://gemini.google.com/app`
     - 프롬프트를 URL 파라미터에 넣지 않는다.

## 프롬프트 품질 점검 (넘기기 전에 반드시)

넘긴 프롬프트의 결과는 우리가 확인할 수 없다. 그래서 내보내기 전에 점검한다. 사용자에게는 결과만 한 줄로 알린다. 예: "애매한 곳 2곳 고쳤어요."

1. **빠진 것 점검** — 아래 일곱 가지가 다 있는지 본다:
   - 목표: 무엇을 만드나
   - 이유와 맥락: 왜 필요하고, 누가 쓰나
   - 독자나 사용자
   - 결과물 형식: 모양, 분량, 구조
   - 지킬 것과 하지 말 것
   - 잘 됐다의 기준: 확인할 수 있게
   - 예시: 말투나 스타일이 중요할 때
2. **빈말을 구체적으로** — "적당히", "깔끔하게", "전문적으로", "좋게", "자세히" 같은 말은 받는 AI마다 다르게 해석한다. 숫자나 예시로 바꾼다. 예: "자세히" → "항목마다 2~3문장, 사례 1개"
3. **맥락 없는 독자 테스트** — 이 대화를 모르는 사람이 프롬프트만 받았을 때 다르게 해석할 수 있는 곳을 찾는다.
   - 서브에이전트를 쓸 수 있으면, 맥락 없는 에이전트에게 최종 프롬프트만 주고 두 가지를 받는다: (a) 애매해서 여러 갈래로 해석될 수 있는 곳, (b) 이 프롬프트로 만들 결과의 요약 3줄.
   - (b)가 사용자가 원한 것과 다르면, 어긋난 곳을 고친다.
   - 에이전트를 쓸 수 없으면 직접 "이 대화를 모르는 사람"이 되어 같은 두 가지를 해본다.
   - 이 테스트는 내용의 애매함을 잡는 용도다. 형식 맞춤은 1번 단계에서 targets.md 규칙으로 한다.
4. **타깃 규칙 확인** — targets.md의 해당 타깃 "하지 말 것"을 어기지 않았는지 본다.
   - 예: 생각하는 모델에게 "단계별로 생각해" 넣지 않기
   - 예: 검색형 AI에 긴 예시 넣지 않기

## 5. 보고 고치기

결과 바로 아래에 짧게 묻는다: `좋아` / `조금 고칠래` / `방향이 달라`

- **조금 고칠래**: 화면 한 장으로 받는다.
  - **슬라이더**: 지금 결과가 있는 위치에 맞춰 둔 상태로 보여준다 ([sliders.md](sliders.md)). 결과를 본 다음이라 감을 잡기 쉽다.
  - **고칠 부분 고르기**: 길이, 말투, 내용, 구조, 디자인, 정확성
  - **가리키기**: "3번째 문단", 또는 스크린샷에 동그라미
- **방향이 달라**: 2단계의 되말하기부터 다시 한다. 어디가 틀렸는지만 고친다.
- **넘긴 경우**: 수정 약속 덕분에 대부분 받는 AI의 창 안에서 끝난다. 그래도 잘 안 풀려서 사용자가 `/preflight 수정`과 함께 결과(붙여넣기나 스크린샷)를 가져오면, 같은 방식으로 묻고 같은 대화창에 붙여넣을 수정 요청 프롬프트를 만들어준다.

## 6. 기억

- 사용자가 쓰는 도구와 모델은 처음 답했을 때 바로 기억한다 (묻지 않고 저장해도 된다고 첫 화면에 한 줄 안내).
- 사용자가 고친 것은 곧 AI의 추측이 틀린 것이다. 같은 종류의 수정이 두 번 나오면, 다음 추측에 쓸 선호로 저장할지 한 줄로 묻는다. 예: "보고서는 늘 쉬운 말로 — 기억해둘까요?"
- 저장한 선호는 1단계 추측에 먼저 쓴다. 그래서 쓸수록 갈림길이 줄어든다.

## 피로 신호

- 이런 신호가 보이면 남은 갈림길을 추천값으로 채우고, "나머지는 제가 정했어요. 결과 보고 고쳐요."라고 알린다:
  - `잘 모르겠어, 추천해줘`를 연달아 2번 고름
  - 답이 점점 짧아짐
  - "아무거나", "몰라", "알아서"라는 말
- 질문은 단계 사이에서만 한다. 실행 도중에 끼어들지 않는다. 실행 중에 생긴 질문은 모아뒀다가 끝나고 한 번에 묻는다. 막혀서 진행이 안 될 때만 예외다.
- 진행률, 결정 기록 표는 🔴이거나 사용자가 원할 때만 보여준다.
